# SPEC-113 — 士気と食料の見直し

SPEC-109 §4・§6.5・§6.6・§7.2 と SPEC-110 の economy / battle / turn / orders の契約を改める **ルールの変更**。
見せ方（内訳・見込み・朝の報告）は SPEC-114 で扱う。この SPEC は、見せ方が使う **見込みの関数** までを用意する。

## 0. なぜ変えるか

プレイテストで「農作しても食料が追いつかない」。エンジンで 8 日回すと、徴兵していないのに兵が 570 → 1,332 人に増え、
1 日の消費が 124 → 274 になって 5 日目に食料が尽きた。原因は 2 つ。

1. **兵がただで増える**: 本拠地の夜の回復（+統率力）、休息（統率力 × 2〜4）、支援・回復ヒーローの隣（上限の 5〜10%）が、人口を使わずに兵を足している
2. **飢えと回復の輪**: 飢えで兵 × 0.9 → その夜に回復 → 翌日また飢える。食料は 0 に張り付き、人口だけが毎日 5% 減る

作者の決定（2026-10-24）: 飢えは **士気** を下げ、士気が 0 になると **兵が少しずつ逃げる**。士気はヒーローのスキルや施策でも上下する。

## 1. 士気（Squad.morale）

- 部隊ごとに **士気 0〜100**（整数）。新しく作った部隊は **60**
- **強さに効く**: 部隊の攻撃力・防御力に `士気係数 = 0.75 + 0.005 × 士気` を掛ける（0 → ×0.75、50 → ×1.00、100 → ×1.25）
- **士気 0 の部隊は逃走する**: 1 日の終わりに兵の **8%（切り上げ）** が逃げる。逃げた兵は消える（人口に戻らない）
- 士気 20 未満は「動揺」として UI が強調する（ルール上の効果は士気係数だけ）

### 1.1 士気が動くとき（1 日の終わり、または出来事のとき）

| 出来事 | 変化 | いつ |
|---|---|---|
| 飢え（その日の食料が足りなかった） | **−15**（そのランドの全部隊） | 1 日の終わり |
| 食料が足りた日 | **+2** | 1 日の終わり |
| 本拠地で夜を越した | **+3** | 1 日の終わり |
| 配給「節約」 / 「増量」（§3） | **−4** / **+4** | 1 日の終わり |
| 指揮（commander）のヒーローが隣にいる | **+2** | 1 日の終わり |
| 休息 | **+10** | 実行のとき |
| 恩賞（§4） | **+20** | 実行のとき |
| 戦闘に勝った（相手を敗走させた・砦を落とした） / 負けた（与えたより受けた兵が多い） | **+8** / **−8** | 戦闘のとき |
| 奇襲を受けた | **−15** | 戦闘のとき |
| 敗走して本拠地へ戻った | **30 にする** | 敗走のとき |
| 砦を落とした（そのランドの全部隊） | **+5** | 陥落のとき |
| 本拠地が落ちて相手に従った部隊 | **30 にする** | 陥落のとき |

上限 100・下限 0 で切る。

### 1.2 ヒーローのスキルと士気

スキルの種類（`hero.skill.kind`）ごとに、**戦闘でスキルが発動したとき** に士気も動く（ダメージや回復の効果に加えて）。

| 種類 | 士気への効果 |
|---|---|
| buff（強化） | 自分の部隊 **+10** |
| heal（回復） | 自分の部隊 **+6** |
| debuff（弱体） | 相手の部隊 **−10** |
| damage（攻撃） | なし |

**部隊の種類（小分類）**: 指揮（commander）は §1.1 の「隣にいる味方 +2」に加え、自分の部隊の士気が毎日 **+2**。
回復（healer）・支援（support）は隣の味方の **士気の減り（飢え・節約）を半分** にする（切り捨て）。

## 2. 兵はただで増えない

- **すべての兵の増加は人口を消費する**（1 人につき人口 1）。本拠地の夜の回復・休息・支援 / 回復ヒーローの隣の回復が対象。
  人口が足りなければ、足りる分だけ増える。人口 0 なら増えない
- 回復の量そのもの（統率力ぶん・統率力 × 2〜4・上限の 5〜10%）は変えない。上限も `統率力 × 10` のまま
- 徴兵は今までどおり人口を兵に移す
- **飢えたときの即時の罰（兵 × 0.9・人口 × 0.95）はやめる**。かわりに §1.1 の士気 −15。人口はその日増えない（自然増なし）
- 本拠地の夜の回復は、**食料が足りた日だけ** 起きる（飢えた夜に兵が戻る輪を断つ）

## 3. 施策：配給（Land.ration）

ランドごとの方針。指示ではなく、いつでも切り替えられる（AP を使わない。部隊の方針と同じ扱い）。

| 配給 | 兵の食料の消費 | 士気 |
|---|---|---|
| 節約 `save` | **× 0.75** | 毎日 **−4** |
| 通常 `normal`（既定） | × 1.0 | ±0 |
| 増量 `feast` | **× 1.25** | 毎日 **+4** |

人口の消費（人口 ÷ 10）は配給に関係しない。

## 4. 施策：恩賞（内政の 5 つ目 `reward`）

- 内政（本拠地でだけ・AP 2）に **恩賞** を足す。GUM を **10 + ceil(兵 ÷ 20)** 払い、**その部隊の士気 +20**
- GUM が足りなければ選べない（`orders.validate` が `gum` の理由で断る）

## 5. 数値の釣り合い（調整してよいつまみと、目標）

ルールの形は上のとおり固定し、**次の 3 つのつまみだけ** を `tools/sim.mjs` と下の目標で調整してよい。
決めた値はこの節の末尾の表に書く。

| つまみ | いまの値 | 調整の範囲 |
|---|---|---|
| 初期の兵（`統率力 × k`。newGame と SOUL） | k = 3 | 1〜3 |
| 兵の食料の係数（兵 ÷ d） | d = 5 | 5〜12 |
| 農作の量（10 + 統治力 × m） | m = 1 | 1〜2 |

目標（プレイヤーのランドを、その遊び方の決め打ちの方針で 28 日回す。`tools/sim.mjs` に方針を足す）:

| 方針 | 目標 |
|---|---|
| 何もしない（指示なし） | 食料は 6 日以上もつ。尽きても 28 日目まで部隊が全滅しない |
| 毎日 1 人だけ本拠地で農作を 1 回 | 1 日目の食料の差し引きが −10〜+5/日 |
| 毎日 1 人が農作を AP いっぱい | 差し引きが +10/日 以上（黒字にできる） |
| 毎日 2 回ずつ徴兵し続ける | 4〜8 日目のどこかで赤字になる（兵を増やすと食料を圧迫する、が体験できる） |
| 全ランド CPU（既存の sim） | 飢え（ランド × 日）が 1 シード平均 30 以下、逃走で兵が 0 になる部隊が 1 シード平均 1 以下、落ちた砦は 1 シード 15〜40 のまま |

決めた値:

| つまみ | 値 | 根拠（sim の結果） |
|---|---|---|
| k | **2** | 1 日目の消費（兵 ÷ d）は ほぼ 統率力の合計 × k ÷ d。「毎日 1 人が農作 1 回」の差し引きを −10〜+5 に入れるには、兵の食料が 1 日 約 40（農作 1 回 = 10 + 統治力 ≒ 43 に、地形の産出 ≒ 9 と人口の消費 10 を足し引きした分）であってほしい。開始の 3 体の統率力の合計は 約 190 なので k ÷ d ≒ 0.21。k = 3 だと d = 12 でも差し引き −3.7・食料 3〜5 日、k = 1 だと d = 12 で +28 と、どちらかに大きく外れる |
| d | **9** | k = 2 で d = 9 が差し引きの平均 +1.5 / +2.6（seed 1〜10 / 11〜20）。d = 10 だと +5.6 / +6.5 で上の端を越える。d が 10 未満なので、徴兵（人口 1 → 兵 1）は食料の消費をわずかに増やす（人口は 1 人 ÷ 10、兵は 1 人 ÷ 9） |
| m | **1** | 調整の範囲の下限。m = 2 だと農作 1 回が 10 + 統治力 × 2 ≒ 76 になり、「農作 1 回」の差し引きが +36（seed 1〜10）まで上がる。「AP いっぱい」は m = 1 でも +98 以上 |

「差し引き」は上限で止めない 1 日の流れ（地形の産出 + 農作の量 − 消費）。UI の「このあと」（breakdown + previewDomestic）は、

**満たせない目標と、その理由**

1. **「何もしない：食料 6 日以上」と「農作 1 回：−10〜+5」は、どのつまみでも同時に満たせない。**
   何もしないで 150 の食料が 6 日もつには、1 日の赤字が 約 25 以下（150 ÷ 6）でなければならない。
   ところが農作 1 回は 10 + 統治力 ≒ 40〜51（いちばん統治力の高いヒーロー）なので、「農作 1 回で −10〜+5」は
   「何もしない日の赤字が 35〜56」と同じことになる。差がおよそ 15〜30 あり、k / d はこの 2 つを同じ向きにしか動かさない
   （m は農作の量を増やす向きにしか動かせない）。決めた値は「農作 1 回」を目標に入れ、そのかわり何もしないと 4〜6 日で食料が尽きる。
   全滅はしない（飢え → 士気 0 → 1 日 8% の逃走で、兵が地形の産出で食べられる数まで減ると止まる）
2. **「徴兵 2 回：4〜8 日目に赤字」は、「差し引きが 0 以上から負に変わる」の意味では満たせない。**
   農作しないランドは 1 日目から赤字：地形の産出は 1 日 4〜14 しかなく、人口 100 の消費 10 だけでほぼ使い切る。
   さらに、本拠地で夜を越すと兵の回復（統率力ぶん × 3 体 ≒ 190）が人口 100 を 1 晩で使い切るので、
   徴兵してもしなくても 2 日目の兵はほぼ同じ（人口は 1 日 1 しか増えない）。徴兵で兵が日を追って増え続けることが、そもそも起きない。
   そのため「食料が尽きる日」で測った（4〜8 日目に尽きる：19 / 20 シード）
3. **目標の外**：CPU の Legendary 攻略は 0 / 20（SPEC-113 の前は 4 / 6）。兵は人口でしか増えないので、CPU の部隊の兵は 28 日目でも
   最大 230〜470（seed 1〜6 の 21 日目。ai の Legendary を狙う下限 `FORT_MIN_TROOPS.legendary = 550` に届かない）。下限を 350 / 400 に下げても
   攻略は 0 / 10 のままだったので変えていない。人口が 0 のときに本拠地へ戻って休む（兵は増えない）のはやめた
   （ai.js の refit・plannedGrowth を人口で頭打ちに。落ちた砦が 1 シード平均 21.4 → 25.2 に増えた）

テスト（`tests/balance.test.mjs`）は seed 3・4 で、範囲を少し緩めて確かめる：何もしない 4 日以上・全滅なし / 農作 1 回 −15〜+10 /
AP いっぱい +10 以上・食料が尽きない / 徴兵 2 回 3〜10 日目に尽きる / CPU 飢え 40 以下・逃走で兵 0 の部隊 2 以下・落ちた砦 12〜45。

## 6. 契約の変更（SPEC-110 に反映する）

### 6.1 state

```js
Squad += { morale: 0..100 }        // 既定 60。古いセーブで無ければ 60 として読む
Land  += { ration: "save"|"normal"|"feast" }   // 既定 "normal"
```

### 6.2 新しいイベント

```js
{ t: "morale", squad, delta, reason: "starve"|"fed"|"home"|"ration"|"commander"|"rest"|"reward"|"win"|"lose"|"ambushed"|"routed"|"fort"|"skill"|"surrender", value }
{ t: "desert", squad, amount }            // 士気 0 で逃げた兵
{ t: "starve", land, shortfall }          // 既存。足りなかった量を足す
```
1 日の終わりの士気の変化は、ランドごとに 1 件のまとめ（`{ t:"morale_day", land, changes:[{squad, delta, reasons[]}] }`）にしてよい（UI の朝の報告がそれを読む）。

### 6.3 関数（すべて純粋関数。UI はこれだけを呼ぶ。UI で計算し直さない）

`economy.js`
- `moraleMult(morale) → number`（§1）
- `setRation(state, landId, ration)`（**mutates**）
- `breakdown(state, db, landId) → { food, gum, mat, pop }`。各資源は
  `{ income: [{ key, label, value, squad? }], expense: [{ key, label, value, squad? }], net, stock, cap, daysLeft }`。
  `daysLeft` は差し引きがマイナスのときだけ `floor(stock / −net) + 1`、それ以外は `null`。行の合計は必ず `net` に一致する。
  兵の消費は部隊ごとの行に分ける（`squad` に id）
- `forecast(state, db, landId) → { food: { net, daysLeft }, gum: {…}, mat: {…}, pop: {…}, troops: { total, cap } }`（breakdown の要約）
- `previewDomestic(state, db, squad, kind) → { ok, reason, delta: { food, gum, mat, pop, troops, morale }, perDay: { food }, repeat }`。
  `repeat` は今の AP であと何回積めるか。`perDay.food` はこの指示で 1 日の食料の差し引きがどう変わるか（徴兵なら兵が増える分の消費のマイナスと、人口が減る分の消費のプラスを合わせた値）
- `previewRation(state, db, landId, ration) → { perDay: { food }, moralePerDay }`
- `domestic` に `reward` を足す。`DOMESTIC_KINDS` は `['conscript','farm','trade','craft','reward']`

`battle.js`
- `power` / `fortPower` に士気係数を掛ける（砦・本拠地は士気 60 扱い）
- `predict(state, db, attacker, target) → { attacker: { before, min, max }, defender: { before, min, max }, label: "overwhelm"|"advantage"|"even"|"disadvantage"|"hopeless", excludes: string[] }`。
  `rng` を使わない。回避・スキルの発動の有無で幅を出す（最小＝相手が回避・自分のスキル不発、最大＝命中・スキル発動）。
  ラベルは「相手に与える見込みの中央 ÷ 自分が受ける見込みの中央」で、2.5 以上 overwhelm、1.4 以上 advantage、0.7 以上 even、0.4 以上 disadvantage、それ未満 hopeless
- `resolve` で §1.1・§1.2 の士気の変化を起こし、`morale` イベントを followups に入れる

`turn.js`
- `finishDay` の順番: 産出 → 消費（配給を掛ける）→ 足りなければ飢え（士気 −15、人口の自然増なし）→ 士気の毎日の変化 → 士気 0 の逃走 → 兵の回復（人口を消費。飢えた日は本拠地の回復なし）→ 霧 → 日曜の集計 → 終了判定
- `noticesFrom` に士気・逃走・飢えの文を足す（「食料が足りず、全部隊の士気 −15」「ヒーロー A の部隊から 23 人が逃げた」）

`orders.js`
- `validate` の domestic に `reward`（GUM 不足は `gum`）

`ai.js`
- CPU も配給と恩賞を使う: 食料が 3 日以内に尽きる見込みなら「節約」、余裕があり士気の平均が 40 未満なら「増量」か恩賞。士気 0 の部隊は本拠地へ戻して休息

### 6.4 セーブ

保存の形が変わるので、読み込みで `morale` / `ration` が無ければ既定値を入れる（古いセーブを捨てない）。

## 7. テスト

- 士気係数、各出来事での士気の変化、上限下限、士気 0 の逃走（8% 切り上げ）
- 兵の増加が人口を消費すること、人口 0 で増えないこと、飢えた日は本拠地の回復が無いこと
- 配給の消費倍率と士気、恩賞の費用と効果と GUM 不足
- `breakdown` の行の合計が `net` と一致すること（複数シード・複数日）
- `predict` の min ≤ 実際の `resolve` の結果 ≤ max（rng を変えて 200 回）
- `tools/sim.mjs` に §5 の方針を足し、目標の表を満たすこと（テストでは 2 シードで、範囲を少し緩めて確かめる）
